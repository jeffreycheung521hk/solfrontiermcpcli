## Summary

`sfcli gate run <config.json>` starts a stdio MCP server for the host. It spawns the configured downstream MCP servers and re-exposes their tools as `<server>__<tool>`, plus `gate__status`. Calls are forwarded verbatim and every step is written to a hash-chained JSONL audit log. Policy (T2), review (T4), checkpoint (T5) and holds (T6) are not referenced. They plug in later by replacing the `callTool` handler (`createDefaultHandlers` in `src/commands/gate.mjs`) and by passing `checkpointUrl` to `startDownstreams`.

## Choices made (see `docs/hackathon/questions/T1.md`)

- The secret-key guardrail runs on comment keys too.
- `upstreamRpcEnv` is required. An empty env var counts as unset.
- `rpcVar`, `walletVar` and `env` may not name `SFGATE_*` or config-named variables.
- A tool nobody listed is refused (`unknown_tool`), not forwarded.
- Tool results are redacted on the way to the host (I4 wins over "verbatim").
- A handler exception → `-32603`, never a forward.
- An audit record that still contains a secret after redaction is not written, and the call fails.
