# T1 — questions (fail-closed choices made; nothing blocked)

1. **Do `_`-prefixed comment keys go through the secret-key guardrail?** SPEC says comments are
   ignored, and also says to walk every key. Choice: the guardrail runs on **every key, comments
   included** (a commented-out `_privateKey` is still a secret on disk). Comments are then dropped.
2. **Is `upstreamRpcEnv` required?** Choice: **yes**. Gate cannot review or checkpoint anything
   without an upstream, and a missing value should be an exit 2 now, not a refusal later.
3. **An env var that is set but empty or whitespace?** Choice: treated as **not set** (exit 2).
4. **Load the petty-cash key when `pettyCash` is configured but no server has `walletVar`?**
   Choice: **yes**, and a missing or malformed file is an exit 2 either way. Later cards use the
   petty-cash pubkey as the wallet under review.
5. **`rpcVar` / `walletVar` / `servers.*.env` keys naming `SFGATE_*` or a config-named variable?**
   Choice: refused (exit 2). Injecting Gate's own names into a child would undo I5.
6. **T1 `tools/call` for a name that no downstream listed.** Choice: not forwarded. It is refused
   with the T2-shaped `unknown_tool` body (`isError: true`), and `downstreams.call` also refuses
   tools the server did not list.
7. **Tool results are redacted on the way to the host.** I4 ("never returned in a tool result")
   wins over "verbatim". A result is changed only when it contains one of Gate's own secrets.
8. **An exception thrown by a handler.** Choice: JSON-RPC `-32603` with a redacted message, never a
   forward. A downstream failure during a forwarded call becomes a `downstream_error` refusal.
