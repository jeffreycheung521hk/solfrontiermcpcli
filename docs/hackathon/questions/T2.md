# T2 — questions (fail-closed choices made; nothing blocked)

All of these live in `src/gate/tool-policy.mjs` (or its wiring in `src/commands/gate.mjs`) and are
pinned by `test/gate-tool-policy.test.mjs`.

1. **`"*"` set to something other than `"deny"`.** The card mentions "`*` matched with `deny`",
   which suggests other values might exist. Choice: `"*"` may only be `"deny"`, and anything else is
   a config error. `"*": "pass"` would undo I1 for every server, including ones added later. To
   allow a whole server, write `"<server>.*": "pass"`.
2. **`showDeniedTools` vs I1 for tools no rule names.** §5.2 says deny-mode tools are hidden unless
   `showDeniedTools`. I1 says a tool that matches no rule "is denied and not listed". Choice: I1
   wins. A tool with no rule, or matched only by `"*"`, is never listed. `showDeniedTools: true`
   lists only explicit denies (exact or glob), with the ` [denied]` suffix.
3. **A rule for a server that is not in `servers`.** Choice: config error. A misspelt `deny` rule
   (`"walet.drain": "deny"`) next to a broader `"wallet.*": "pass"` would otherwise let the tool
   through without a word.
4. **`bound` with nothing to bind** (`"bound"` as a string, or `args: {}` and no `txArg`).
   Choice: config error. It would be `pass` under a name that tells the agent and the human the
   tool is guarded.
5. **`args` / `txArg` / `txArgEncoding` on a `pass` or `deny` rule, or an object rule without
   `mode`.** Choice: config error. There is no default mode, and constraints are never silently
   ignored.
6. **Default `txArgEncoding`.** Choice: `base64`. Both example configs, web3.js and Jupiter Ultra
   use it. A wrong encoding still fails closed later, at decode (`tx_decode_failed`, T4).
   `txArgEncoding` without `txArg` is a config error.
7. **Must the `txArg` argument be present?** Choice: yes, always, and it must be a string, even
   if `args` declares it `required: false`. A transaction-bearing tool called without its
   transaction has nothing to review (`arg_missing` / `arg_type`).
8. **Untyped constraints.** Choice: `gte` / `lte` need `type` `number`, `integer` or
   `number-string`, otherwise it is a config error (no coercion). `in` / `pattern` without a
   `type` require a string value. A constraint with only `required` accepts any present value.
   `in` on a numeric type is a config error. So is `pattern` on `number` / `integer`.
   `number-string` may take a `pattern`, which is tested against its raw text.
9. **What a `number-string` is.** Choice: `^-?[0-9]+(\.[0-9]{1,18})?$`, at most 80 characters.
   Leading zeros (`"00.5"`) are allowed. A JSON number is `arg_type`, not coerced. So is a 19th
   decimal place, even a trailing zero, because the value cannot be represented at 10^18. Config
   bounds may be numbers (expanded from their shortest form, so `1e-7` → `"0.0000001"`) or decimal
   strings.
10. **`null` arguments.** Choice: `null` counts as absent. It is `arg_missing` when required and
    allowed when `required: false`.
11. **`gte` above `lte`.** Choice: config error (nothing could pass, so it is a typo).
12. **Order inside `gate run`.** Choice: policy first. A refusal never waits for downstreams to
    start. A tool the policy allows but no running downstream listed is still `unknown_tool`
    (T1 behaviour, kept). A `txArg` tool that passes its constraints is refused with
    `approval_unavailable` until I1 lands.
13. **Audit `tool_call.decision`.** Choice: `"deny"` for every refusal, otherwise the rule's mode
    (`"pass"` / `"bound"`). T1's `"forward"` / `"t1-forward-all"` is gone. Refused records also
    carry `mode`, `rule`, `code` and `violations`. `approval_unavailable` records carry `txArg`
    (the argument name). `gate_start` records the policy summary, so the log says what later
    decisions were judged by. `tool_list` records `hidden` (how many downstream tools were hidden).
14. **T1's `test/gate-core.test.mjs` assumed forward-all.** Under default deny its two stdio
    round trips had nothing to call. Choice: those two configs now carry an explicit pass policy
    (`"fake.*": "pass"`, `"echo.leak": "pass"`). No assertion was changed.
15. **Policy errors vs environment errors.** `compileToolPolicy` runs right after
    `loadGateConfig`, which also checks the environment, so a missing env var is reported before a
    policy mistake. Both are exit 2 before the audit log is opened or anything is spawned.
16. **`refusal()` with an unknown code.** Choice: `TypeError`, because it is a programming error.
    It still never forwards: the host server answers `-32603`.
17. **How much a hint discloses.** Lists are shown by name and size (`to in @allowlist (1 value)`).
    Literal `in` arrays of up to 5 values are shown in full, so the agent can pick an allowed mint.
    An observed string longer than 120 characters is truncated in a violation.
