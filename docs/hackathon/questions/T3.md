# T3 — questions and the fail-closed choices made

1. **Watch set over 40 addresses.** SPEC §5.4 says "max 40". A wallet with many token accounts
   (or a caller passing many destinations) can exceed it. Trimming would hide balance changes,
   so `simulateWithDeltas` throws (`too many accounts to watch`) and the caller refuses.
   Consequence: a wallet holding > ~39 token accounts cannot transact through Gate until this
   is revisited (e.g. split into several simulate calls). *Choice: refuse.*

2. **Token accounts whose ownership leaves the wallet.** SPEC says a post-state account owned by
   the wallet counts as own. The reverse case (owned before, closed or `setAuthority` to someone
   else after) is not specified. *Choice:* it stays in `tokens` with `post: 0n`, so the full
   balance is reported as outflow.

3. **Same account, different mint before/after** (closed and re-initialised inside one tx).
   *Choice:* two rows, one per mint (`pre → 0`, `0 → post`).

4. **`verifySignatures().complete`.** *Choice:* true only if every slot holds a present (non-zero)
   and valid signature; an empty signature list is never complete.

5. **Malformed data in a recognised instruction** (too short, too few accounts, invalid memo
   UTF-8). *Choice:* `describeInstructions` throws, so T4 reports `tx_decode_failed`.
   Unrecognised tags of known programs and all unknown programs are `kind: 'unknown'`.

6. **Extra Ix fields.** Beyond SPEC's Ix shape, the kit adds `units` / `microLamports` / `bytes`
   (compute budget), `authorityType` / `newAuthority` (setAuthority) and describes
   `transferWithSeed`, `withdrawNonceAccount`, `mintTo`, `burn`, `burnChecked`, `revoke`. Additive
   only; T4 may ignore them. Note for T4: `transferWithSeed` and `withdrawNonceAccount` move
   lamports to `destination` too.

7. **Decoder strictness beyond the card.** Also rejected: signature count ≠
   `numRequiredSignatures`, `numReadonlySigned ≥ numRequiredSignatures`, duplicate static keys,
   duplicate or empty lookup entries, program id index 0 (fee payer), > 256 total keys.
