# T6 questions (holds and approval)

Each entry: the question, the fail-closed choice made, and where it lives. None of these blocked
the card; the human can overturn any of them.

1. **Where does the hold queue learn the approver?** SPEC §5.6 gives `approve(id, { publicKey,
   signature, method })` but no constructor. Choice: `new HoldQueue({ approver })`. Without an
   approver, no wallet approval succeeds (`approval_unavailable`, 503). The approval server checks
   the signature too, and refuses to start if its `approver` differs from the queue's.
   I1 must construct the queue with `{ approver: config.approver }`.

2. **Can review text contain a newline?** The message must be exactly six lines; a `summaryLine`
   carrying `\n` could forge an `expires:` line in the wallet popup. Choice: control characters
   and U+2028/U+2029 in the summary become spaces. A hold whose hash, cluster or id is malformed is
   not created at all (`add()` throws, so I1 refuses the call).

3. **Is `startApprovalServer` sync or async?** Listening is asynchronous. Choice: configuration
   errors (unknown method, `local-button` on `mainnet-beta`, bad or mismatched approver) throw
   synchronously before anything listens; otherwise it returns a promise of `{ url, port, close }`.

4. **`{ method: 'local-button' }` posted while the server runs in `wallet-signature` mode?**
   Choice: 403 `method_not_allowed`, hold stays pending. The queue independently refuses
   local-button approval for any hold whose cluster is not devnet/localnet.

5. **What may `notifyHold` open?** `open` / `xdg-open` will launch `file://` paths and custom URL
   schemes. Choice: only `http://127.0.0.1:<port>/…` or `http://localhost:<port>/…` is opened;
   anything else is silently dropped (the notification still shows). `openUrl: false` maps to
   `approval.openBrowser: false`.

6. **`timeoutSec` bounds inside the queue?** Config validation is T1's. Choice: the queue also
   refuses `timeoutSec` ≤ 0 or > 60 (SPEC §5.1 maximum).

7. **Who may reject?** Any request that passes the Host/Origin checks can reject a pending hold
   ("Reject is always allowed while pending"). A local process can forge Host/Origin, so a rogue
   local process could reject holds. That only ever refuses money movement, so it is accepted.
